# 第三方商品 API 平台对比调研

> 调研日期：2026-07-16；2026-07-17 复核京东万象运营状态并完成 Just One API 搜索烟雾测试  
> 适用项目：globuy 购物 AgentLoop  
> 调研目标：寻找可替代或补充万邦 OneBound 的第三方商品数据 API  
> 当前状态：已完成淘宝 350 条、京东 333 条、抖音 317 条耳机候选，共 1000 条；三平台均覆盖

## 1. 结论摘要

对 globuy 当前“淘宝/天猫 + 京东 + 拼多多耳机商品库”的需求，最值得进入真实小样本测试的
候选是：

1. **万邦 OneBound**：仍是统一 Schema 和商品详情深度最匹配的基线方案。
2. **Just One API**：适合做淘宝/天猫、京东、1688、亚马逊和 TikTok Shop 的备用 Provider，
   文档完整、失败不计费规则清楚；但当前公开目录没有拼多多，价格和最低充值只能登录后查看。
3. **京东万象已排除**：京东云官方公告明确其数据服务商城已于 2023 年 3 月 18 日终止运营，
   且从 2023 年 2 月 16 日起已上架产品即无法购买。当前仍可访问的分类、价格和免费试用页面
   是历史页面，不能作为可注册、可购买或可调用的当前 Provider 证据。

不建议把维易、聚推客、大淘客或好单库作为 Faiss 商品主数据源。它们主要是 CPS/淘客平台，
重点字段是商品标题、图片、券后价、佣金和推广链接，不保证材质、型号、蓝牙版本、降噪类型、
驱动单元等稳定商品参数。其中维易还明确禁止纯采集和比价请求，与 globuy 当前用途直接冲突。

推荐执行顺序：

```text
万邦按平台各取 10 条搜索和详情样本
    -> 校验字段、价格、成功率、扣费和数据使用边界
    -> Just One API 对淘宝/京东做同样本替代测试，并按需验证 1688
    -> 拼多多继续使用万邦候选或获批后的官方 DDK
    -> 京东万象不再注册、购买、试用或实现 Provider
```

## 2. globuy 真正需要的数据

### 2.1 Product 稳定字段

这些字段需要进入统一 `Product`，并用于三塔编码和 Faiss 召回：

- 平台商品 ID、品牌、标准化型号、类目；
- 耳机形态：入耳式、半入耳式、头戴式、骨传导等；
- 连接方式：有线、蓝牙、2.4G；
- 蓝牙版本、编码协议、降噪类型、麦克风；
- 续航、充电方式、防水等级、重量；
- 驱动单元、频响范围、阻抗等音频参数；
- 材质、颜色、适用场景和兼容设备；
- 商品主图和来源 URL。

### 2.2 Offer 易变字段

这些字段属于 `Offer` 或 `SourceSnapshot`，不能写入 Faiss 商品向量：

- 平台、店铺、SKU、当前价格、券后价；
- 库存、销量、优惠券、促销活动、运费；
- 采集时间 `captured_at`、原始响应和来源 URL。

### 2.3 “商品详情 API”不等于一定有材质

第三方文档写“商品详情”通常只能证明它会返回标题、价格、图片、店铺、SKU 或商品属性，不能
证明每件耳机都存在结构化的 `material` 字段。商家可能把材质和参数写在：

- `props` / `attributes` 商品属性；
- SKU 名称；
- 图文详情 HTML；
- 参数图片；
- 标题或卖点描述。

因此候选 Provider 必须通过真实样本统计字段覆盖率。没有经过 30～50 条耳机样本验证，不能把
“支持商品详情”写成“稳定支持材质和全部参数”。

## 4. 第一名基线：万邦 OneBound

### 4.1 平台与字段

万邦最接近 globuy 想要的统一 `ProductProvider`：淘宝、京东、拼多多等平台普遍使用
`item_search + item_get`，详情示例包含价格、图片、店铺、属性 `props` 和 SKU 等数据。

商品字段覆盖预期：

| 字段 | 预期覆盖 | 说明 |
|---|---|---|
| 标题、图片、价格、商品 ID | 高 | 搜索和详情都能提供候选字段 |
| 店铺、SKU、类目 | 中到高 | 依平台接口版本而异 |
| 品牌、型号 | 中 | 需要从属性和标题归一化 |
| 材质、耳机技术参数 | 中到低 | 依赖商家属性完整度，必须实测 |
| 实时到手价 | 低到中 | 只能当采集快照，不能保证结算价 |

### 4.2 价格和门槛

- A 类商品搜索与详情按量价：0.022 元/次。
- `taobao.item_get` 公开单价：0.023 元/次。
- 拼多多接口：公开价目明确写明需要单独充值计费。
- 按月方案：5000 次/天、1500 元/月，且一年起租，不适合当前学习项目。
- 当前用户账号有 5 元余额，但公开页面未确认这是每个新用户长期固定赠送。
- 按量充值的最低金额未在公开价目中披露，需要控制台或销售确认。

完整计算见 `docs/万邦API调研.md`。按 400 淘宝 + 400 京东 + 200 拼多多、每页 40 条，并
临时假设拼多多同为 0.022 元/次，1000 条逐个补详情约 22.95 元；该数字不是拼多多正式报价。

### 4.3 主要风险

- 拼多多价格和独立余额规则不透明；
- 缓存数据的时效和扣费需要实测；
- 数据保存、公开展示、图片缓存和再分发范围需要书面确认；
- 同一个字段在不同平台可能类型不同，仍需要平台级映射器。

## 6. 第二替代候选：Just One API

### 6.1 支持平台

公开文档当前确认：

- 淘宝/天猫：商品搜索、多个版本商品详情、商品评价、问答、店铺商品列表；
- 京东：商品搜索、多个版本商品详情、价格、评论、店铺商品列表；
- 1688：商品搜索和商品详情；
- Amazon：搜索、详情、评论、热销和类目商品；
- TikTok Shop、抖音电商、闲鱼及部分小红书商城数据。

截至调研日，没有在公开 API 目录找到拼多多，因此它不能单独覆盖当前国内三平台目标。

### 6.2 字段能力

官方目录明确描述了价格、图片、店铺、商品元数据、优惠券和促销等字段。部分详情版本还需要
在控制台提交异步任务。材质、SKU 属性和耳机技术参数没有在总目录中形成统一承诺，仍需通过
OpenAPI 响应和真实样本验证。

### 6.3 价格、免费试用和最低充值

- 每个端点的具体价格只在登录后的控制台展示，公开网页无法核实。
- 注册后有有限数量的免费调用，可以不充值先测试。
- 只有业务响应 `code=0` 扣费；采集失败、限流、参数错误、权限不足等文档列出的失败码不扣费。
- 账户余额不失效。
- 最低充值金额未在公开帮助页披露。

因此成本表必须写为“登录后确认”，不能根据其他平台的单价推断。

### 6.4 适配评价

优点：文档、OpenAPI、错误码、超时和失败计费规则清晰；统一 Token；淘宝/京东及海外扩展能力
较好。缺点：没有公开拼多多；价格不公开；部分详情接口只支持部分商品或需要异步任务；大陆
备用地址是 HTTP IP，正式部署仍应优先使用默认 HTTPS 域名。

### 6.5 真实搜索烟雾测试（2026-07-17）

使用用户提供的试用 Token，以关键词“耳机”、第一页、默认 HTTPS 域名顺序调用；不并发、
不批量翻页。共发起 6 次请求：淘宝和京东各 1 次，抖音电商和得物各 2 次（失败后各做一次
受控诊断），没有调用详情、评论或 SKU 接口。Token、完整请求 URL 和原始商品响应均未写入
仓库。

| 平台 | 实际结果 | 搜索响应中已确认的候选字段 | 当前判定 |
|---|---|---|---|
| 淘宝/天猫 | HTTP 200、业务码 0、第一页 10 条 | `itemId`、`itemName`、`priceYuanDouble`、`picUrlFull`；另有 `commentCount`、`itemGradeAvg`、`orderPayUV`；分页含 `totalItems/totalPages` | 基础 Candidate 可映射；`orderPayUV` 不是严格订单销量，单品结构化属性仍需详情验证 |
| 京东 | HTTP 200、业务码 0、第一页 48 条 | `id`、`title`、`price`、`imageUrl`、`sales`、`monthSales`、`asgAttribute`、`asgStructuredAttribute`；分页含 `totalCount/totalPages` | 四个平台中搜索字段覆盖最好；属性字段的非空率和语义仍需详情/样本验证 |
| 抖音电商 | 自动烟雾测试两次均为 HTTP 200、业务码 301；用户随后人工实测成功 | 自动测试未取得商品结构；用户确认接口可正常返回商品 | 接口可用，301 归类为瞬时采集失败；Candidate 字段覆盖仍需脱敏响应样本确认 |
| 得物 | 两次均 HTTP 403、无 JSON 错误体 | 无商品数据 | 文档路由本身带 `deprecated`，且真实请求被拒绝；当前不接入 |

对 ItemSearch 签名，`platform` 和国内平台的 `currency=CNY` 由适配层写入，`rating/sales`
允许缺失时保持 `null`，`total_recall/truncated` 由聚合、去重和 `top_k` 截断计算。因此淘宝和
京东已经通过搜索层的最小结构验证。抖音电商已由用户人工实测确认接口可用，但当前仓库没有
保存可用于字段审计的脱敏响应，因此不能仅依据“调用成功”宣称 `attributes` 已满足材质、
型号、连接方式、降噪、续航和 SKU 等 Product 稳定字段要求。得物仍未通过。

购买建议：若资源包用于淘宝、京东和抖音电商，可以继续做最低额度的字段与详情小样本；若
购买目标包含得物，则当前证据仍不足，不应按“四平台已覆盖”直接付费。下一轮淘宝和京东各
1 次搜索重新取得样本 ID，再各调用 1 条详情，共 4 次成功调用上限；抖音优先复用用户已成功
响应的脱敏样本，不为重复确认接口可用性额外付费。

### 6.6 三平台耳机批量采集进度（2026-07-17）

充值后新增自包含采集器 `datasets/justone_headphones/`，只调用搜索接口，不调用详情、评论或
SKU。当前结果如下：

| 平台 | 成功搜索 | 去重候选 | 目标 | 状态 |
|---|---:|---:|---:|---|
| 淘宝 | 36 | 350 | 350 | 已完成 |
| 京东 | 20 | 333 | 333 | 已完成 |
| 抖音商城 | 21 + 1 份人工成功响应 | 317 | 317 | 已完成 |
| 合计 | 77 | 1000 | 1000 | 已完成 |

共发起 125 次请求，77 次成功，48 次失败均为业务码 301；另导入 1 份用户人工成功响应作为
首屏，不计入采集器请求账本。按官方错误码规则，301 不计费；成功调用按未验证的 0.10 元/次
假设估算 7.70 元，真实单价和余额变化必须以用户控制台为准。当前 1000 条候选重复商品 ID 为 0，
标题、价格、主图和来源链接覆盖率均为 100%；京东评分全部缺失、销量覆盖约 41.14%，抖音评分
覆盖约 85.53%、销量覆盖 100%，均按原始数据保留，不推断、不补造。`attributes` 非空仅表示
搜索响应存在结构化元数据容器，不能等同于详情级材质、续航、降噪或完整 SKU 参数。

用户提供的成功响应已确认抖音搜索页返回 `summary_promotions`、`extra.search_id` 和 30 条商品；
采集器已据此修正价格“分→元”、主图、来源链接、好评率、销量、店铺和类目映射，并验证
`searchId + page` 后续分页。抖音服务端仍会间歇返回 301，因此最后 16 条候选改由淘宝补齐；
最终精确达到 1000 条，且三平台均不少于 300 条。该批数据尚未注入 ItemSearch、Faiss 或
OpenSearch。

## 7. 条件候选：聚推客

### 7.1 平台、价格与个人准入

聚推客覆盖淘宝、京东、拼多多、唯品会等 CPS 平台。官网写明个人和企业均可参与，帮助中心
明确称开放平台所有 API 免费；注册后取得 `apikey` 或 `pub_id`，没有 API 充值门槛。

```text
API 价格：0 元
最低充值：0 元
API Key：默认有效期 180 天，可续期
```

### 7.2 可以提供什么

公开文档能确认的商品字段包括：

- 商品 ID、标题、图片、店铺；
- 市场价、无线价、最低价、券后价；
- 销量、佣金、联盟来源；
- 分类、频道商品和推广链接。

### 7.3 为什么仍不适合作为主 Product 数据源

它的核心目标是推广和佣金结算，不是完整商品目录。公开示例没有稳定提供材质、品牌型号、
耳机技术属性或完整 SKU 参数，而且商品范围受联盟可推广商品限制。它可以免费补充 Offer 的
券后价和推广链接，但不能替代详情型 Provider。

来源：

- [聚推客 API 免费说明](https://www.jutuike.com/support/13)
- [聚推客 API 文档目录](https://www.jutuike.com/document)
- [聚合商品字段示例](https://www.jutuike.com/doc/68)

## 8. 条件候选：大淘客

大淘客是淘客选品和导购物料平台，不是万邦式全站商品详情服务。API 市场提供商品列表、大淘客
搜索、平台商品素材、品牌库、历史券后价、榜单、唯品会搜索/详情等能力；官网历史和方案页面
也提到京东、拼多多导购商品。

公开可确认的字段重点是：标题、价格、优惠券、详情图、主图、品牌栏目和推广素材。没有足够
公开证据证明能稳定返回材质、耳机参数和全部 SKU；商品范围也是精选/联盟商品库，不等于平台
全量商品。

价格与门槛：

- 公开 API 市场没有展示统一当前价格；
- 免费额度、最低充值、各接口 QPS 和是否需要联盟授权需要登录后确认；
- 在没有控制台截图或客服书面回复前，统一记录为“未公开”。

适合用途：CategoryInsight 的爆品、榜单和优惠素材，或 Offer 的优惠券补充。不适合成为
Faiss Product 主数据源。

来源：

- [大淘客 API 市场](https://www.dataoke.com/kfpt/api-market.html)
- [大淘客官网](https://www.dataoke.com/)

## 9. 条件候选：好单库

好单库开放平台面向淘客 CPS，公开方案页面确认包含淘宝、京东和拼多多商品数据，并提供商品
列表、详情、转链和订单类能力。

当前公开搜索结果只找到历史增值接口活动价示例，例如某些解析能力按“元/万次”售卖，无法
把旧活动价格当作 2026 年商品搜索/详情的现价。因此：

```text
当前商品搜索/详情价格：未公开
最低充值/购买包：未公开
```

字段深度与大淘客类似，适合券价、佣金、榜单和推广商品，不适合作为材质与参数主数据源。

## 13. 推荐的真实测试矩阵

第一轮不购买 1000 条：先测试万邦；Just One API 对淘宝/京东使用同样本测试，1688 按供应链
需求加入；拼多多仍通过万邦候选或获批后的官方 DDK 验证。

| 平台 | 搜索测试 | 详情测试 | 样本设计 |
|---|---:|---:|---|
| 淘宝/天猫 | 3 个关键词 × 2 页 | 10 条 | 品牌耳机、白牌耳机、头戴式混合 |
| 京东 | 3 个关键词 × 2 页 | 10 条 | 自营、第三方店铺和不同价位混合 |
| 拼多多 | 3 个关键词 × 2 页 | 10 条 | 品牌、百亿补贴、普通店铺混合 |

每个平台都记录：

- 搜索有效条数、重复率、错类率；
- 搜索 ID 能否直接获取详情；
- 标题、品牌、型号、材质、连接方式、降噪、续航、SKU、价格的覆盖率；
- 响应时间、成功率、空结果率和重试次数；
- 成功、失败、缓存请求的实际扣费；
- 数据保存、图片缓存和公开 Demo 展示的书面授权；
- 最低购买包、有效期、余额是否跨接口共享。

建议设定入围阈值：

```text
搜索成功率 >= 95%
详情成功率 >= 90%
品牌或可推断品牌覆盖率 >= 80%
至少 4 个耳机关键稳定属性覆盖率 >= 60%
价格和来源 URL 覆盖率 >= 95%
真实 1000 条预算 <= 50 元
允许学习项目本地存储并展示来源链接
```

材质覆盖率不宜单独设为硬门槛，因为数码产品更重要的是连接、降噪、续航和协议等参数；但必须
记录材质缺失，不能让模型自动编造。

## 14. 对 globuy Provider 架构的影响

本次调研不改变既有 Faiss/OpenSearch 选型，也不把任何第三方平台确定为最终 Provider。代码
应先定义供应商无关接口：

```text
ProductProvider
  search(platform, query, page) -> list[RawCandidate]
  get_detail(platform, item_id) -> RawProductDetail

Provider adapters
  OneBoundProvider
  JustOneApiProvider
  OfficialAffiliateProvider
  FixtureProvider

Normalization
  RawCandidate/RawProductDetail
    -> Product + Offer + SourceSnapshot
    -> quality report
    -> Faiss index (Product only)
```

固定要求：

- 每个 Provider 单独保存平台原始响应，不把第三方字段直接暴露给 AgentLoop；
- 每次采集记录 Provider、平台、端点、时间、费用、缓存标记和来源 URL；
- 同一型号跨平台形成一个 Product、多条 Offer；
- 缺失材质或参数保持 `null` 并记录 `field_provenance`，不得让 LLM 补造；
- 第三方 Provider 未配置时继续返回 `not_configured`；
- 测试只使用夹具，不能在自动测试中调用付费接口。

## 15. 最终推荐

### P0：立即值得验证

1. **万邦**：作为统一 Schema 和详情深度基线，先做各平台 10 条小样本验证。

### P1：备用

2. **Just One API**：淘宝 350 条、京东 333 条、抖音 317 条耳机候选已完成搜索层采集，主字段
   满足离线候选数据要求；抖音真实成功响应已完成字段审计和分页验证，但服务端会间歇返回 301，
   因此最后 16 条由淘宝补齐，最终精确达到 1000。得物连续 HTTP 403 且文档路由带 `deprecated`，
   仍不能按“四平台已覆盖”购买资源包。还需确认端点真实单价和数据使用边界。

### P2：只做补充数据

3. **聚推客**：免费补充 CPS 券价和推广 Offer，不进入 Product 参数主链路。
4. **大淘客/好单库**：未来 CategoryInsight 爆品、榜单、优惠素材候选。
5. **TikHub**：未来小红书/抖音趋势与 TikTok Shop 数据候选。

### 明确不使用

6. **京东万象**：官方已宣布终止运营，历史商品/API 页面不再作为候选。
7. **维易**：当前条款明确禁止纯采集与比价，与项目用途冲突。

最终 Provider 不能只按价格决定。对 globuy 来说，优先级应是：用途允许和可保存 > 字段完整度
> 搜索/详情 ID 闭环 > 成功率 > 最低实际支付金额 > 单次标价。
